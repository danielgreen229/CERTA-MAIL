# Эксплуатация

## Запуск

**Docker (любая машина):**

```bash
docker compose up -d                                              # CPU, Qwen3-8B
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d   # NVIDIA, Qwen3-14B
```

Первый запуск скачивает модель в том `leads-llm` (5 ГБ для 8B, 9 ГБ для 14B, с
проверкой SHA-256), затем поднимает `llm` → `web` → `worker`. Адрес:
`http://127.0.0.1:8000` (`LEADS_PUBLISH=0.0.0.0:8000` — открыть наружу, лучше за
обратным прокси с HTTPS). Начальный пароль администратора:

```bash
docker compose exec web cat /data/initial-admin.txt
```

**Без Docker:** `bash start.sh` (первый запуск ставит окружение и модель), остановка —
`bash stop.sh`.

## Требования

| Вариант | Память | Примечание |
|---|---|---|
| CPU, `qwen3-8b` | от 12 ГБ ОЗУ | 15 заявок ≈ 30–60 мин на 8–16 vCPU; обработка фоновая |
| CPU, `qwen3-4b` | от 8 ГБ ОЗУ | быстрее, качество не проверено набором |
| NVIDIA, `qwen3-14b` | ~11 ГБ видеопамяти | 15 заявок ≈ 3 мин |

## Данные и настройки

| Где | Что |
|---|---|
| том `leads-data` → `/data` (или `data/`) | `leads.json`, `app.db`, `uploads/`, `runs/`, `backups/` |
| том `leads-llm` → `/llm` | файлы модели |
| `.env` рядом с compose (не в git) | секреты и переменные (`LEADS_LLM_MODEL`, `LEADS_PUBLISH`, …) |

Повторный запуск и пересоздание контейнеров данные не трогают: рабочий
`leads.json` создаётся из исходника, только если его нет.

## Диагностика

- `GET /api/health` — файл заявок читается, база отвечает, активная задача и время
  последней отметки обработчика.
- `docker compose logs -f worker` / `data/.run/worker.log` — ход прогона: каждый вызов
  MCP-инструмента с длительностью.
- `runs/<run_id>/run.json` — модель, версия правил, длительность, вызовы по
  инструментам, ошибки по кодам, токены; `trace.jsonl`, `mcp_trace.jsonl` — трейсы;
  `python -m lead_assistant.diagnose runs/<run_id>` — разбор сбоя по слоям.
- `leads-doctor --live` — проверка установки и реальный вызов модели.
- Экран «Обработка» — состояние задач, попытки, причина ошибки; «Настройки» —
  журнал действий.

## Резервная копия

```bash
leads-backup create                     # data/backups/leads-backup-<время>.tar.gz
docker compose exec web leads-backup create
leads-backup restore <архив>            # при остановленных web и worker
```

Копия содержит `leads.json` (снят под блокировкой), согласованный снимок SQLite,
загруженные документы и контрольные суммы. Восстановление проверяет суммы и
перед заменой сохраняет текущие данные в `data/backups/before-restore/`.

## Сбои

| Симптом | Что делать |
|---|---|
| Задача «в очереди», обработчик не берёт | проверить `worker` (логи, `/api/health` → `worker_heartbeat`) |
| Задача упала с `LLM_*` | сервер модели недоступен: `docker compose ps llm`, логи `llm`; задача повторяется до 3 раз |
| `STORAGE_CORRUPT` в `/api/health` | файл заявок повреждён: восстановить из копии; запись в повреждённый файл не выполняется |
| Обработчик остановлен посреди задачи | после запуска задача вернётся в очередь через 90 с и продолжится; записанные заявки не перезаписываются |
| Часть заявок не записана | «Обработать новые / повторить ошибочные» — обработаются только оставшиеся `new` |
