# AI-помощник менеджера по заявкам

Агент разбирает новые заявки логистической компании: назначает категорию и
приоритет, готовит черновик ответа на языке клиента и формирует сводку. Ответы
отправляет менеджер. Заявки лежат в JSON-файле на вашем сервере; агент работает с
ними только через три MCP-инструмента.

Модель — бесплатная и локальная: открытая Qwen3 на сервере `llama.cpp`. Регистрация,
ключи и интернет во время работы не нужны; данные заявок не покидают сервер.

Описание процесса и критерии успеха: [docs/PROCESS.md](docs/PROCESS.md).

## Рабочее место менеджера

Веб-интерфейс: список заявок с поиском и фильтрами, карточка (обращение, извлечённые
сведения, основания, черновик, следующий шаг, источники), «Принять / Исправить /
Отклонить» с историей, фоновая обработка, очередь проверки, база знаний,
подключения, показатели качества, роли.

```bash
docker compose up -d                                                 # CPU, Qwen3-8B
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d # NVIDIA, Qwen3-14B
bash start.sh                                                        # без Docker
```

Адрес: `http://127.0.0.1:8000`. Начальный пароль администратора — в
`data/initial-admin.txt` (в Docker: `docker compose exec web cat /data/initial-admin.txt`),
его нужно сменить при первом входе. Архитектура и хранилища —
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), эксплуатация, диагностика и резервные
копии — [docs/OPERATIONS.md](docs/OPERATIONS.md).

## Установка на чистом Ubuntu

Нужны Python 3.12 и доступ в интернет на время установки (PyPI, GitHub, Hugging
Face). Всё ставится в каталог проекта, от обычного пользователя; каталог может
содержать пробелы.

```bash
sudo apt install python3.12 python3.12-venv      # один раз, если Python 3.12 не установлен
tar -xzf lead-assistant-1.0.0.tar.gz
cd lead-assistant
scripts/install.sh                               # спросит модель и сборку, скачает их
```

Установщик создаёт `.venv`, ставит зависимости по хешам, скачивает сервер
`llama.cpp` и модель в `.llm/` (с проверкой SHA-256) и запускает проверку. Без
вопросов: `scripts/install.sh --model qwen3-14b --build vulkan`. Если модель не
указана, установщик берёт рекомендацию для машины: с видеокартой — `qwen3-14b`,
без неё — по объёму памяти (от 24 ГБ — `qwen3-14b`, от 12 ГБ — `qwen3-8b`).

| Модель | Диск | Память | Когда выбирать |
|---|---|---|---|
| `qwen3-14b` | 9,0 ГБ | ~11 ГБ видеопамяти или ~17 ГБ ОЗУ | рекомендуется: проходит набор для оценки целиком |
| `qwen3-8b` | 5,0 ГБ | ~6 ГБ видеопамяти или ~10 ГБ ОЗУ | сервер без видеокарты и с небольшой памятью; набор для оценки целиком не проходит (см. `REVIEW.md`) |
| `qwen3-4b` | 2,5 ГБ | ~6 ГБ ОЗУ | слабый сервер; не оценивалась |

Младшие модели ошибаются чаще. Защитные правила в коде не дают им потерять заявку
или завысить приоритет без основания, но категорию и черновик после них нужно
проверять внимательнее. Для результата приёмочного качества используйте
`qwen3-14b`.

Без видеокарты модель работает медленно. Замер на 10-ядерном настольном
процессоре: `qwen3-8b` генерирует около 4 токенов в секунду, 14 заявок
обрабатываются примерно за 40 минут. Для запуска по расписанию это приемлемо. С
видеокартой (16 ГБ) `qwen3-14b` обрабатывает те же 14 заявок за 2,8 минуты.

| Сборка | Когда выбирать |
|---|---|
| `cpu` | сервер без видеокарты; работает везде |
| `vulkan` | видеокарта NVIDIA, AMD или Intel с драйвером Vulkan |
| `cuda` | видеокарта NVIDIA; библиотеки CUDA 12.8 скачиваются со сборкой |

Проверка установки:

```bash
.venv/bin/leads-doctor            # окружение, файл, MCP через stdio, модель и сервер на месте
.venv/bin/leads-doctor --live     # плюс короткий реальный прогон с моделью
```

## Запуск

```bash
.venv/bin/process-leads                                   # data/leads.json
.venv/bin/process-leads --leads-file /srv/crm/leads.json  # или переменная LEADS_FILE
```

Команда поднимает сервер модели, печатает вызовы инструментов, сводку и путь к
артефактам прогона `runs/<run_id>/`, затем останавливает сервер. Код возврата:
`0` — все найденные заявки учтены как обработанные, `1` — часть не обработана,
`2` — прогон не состоялся. Повторный запуск безопасен: обработанные заявки не
перезаписываются.

Выбор модели при запуске (порядок: параметр → переменная окружения → выбор,
сохранённый установкой → значение по умолчанию):

```bash
.venv/bin/process-leads --model qwen3-8b --build cpu      # другая модель на этот запуск
.venv/bin/process-leads --choose                          # выбрать из списка и запомнить
.venv/bin/process-leads --llm-url http://localhost:11434/v1 --model qwen3:14b
```

`--llm-url` подключает любой сервис с OpenAI-совместимым API (Ollama, LM Studio,
vLLM, облачный сервис с ключом в `LEADS_LLM_API_KEY`); локальный сервер тогда не
запускается. Остальное: `--today` (дата, от которой считается срочность),
`--batch-size` (заявок на сессию модели, по умолчанию 5), `--skip-model-if-empty`
(для расписания), `--save-dialog` (сохранить полный диалог с моделью), `--think`
(режим рассуждений модели, медленнее).

### В Claude Code

Если у вас есть Claude Code, тот же MCP-сервер и те же правила работают в нём:
проектный `.mcp.json` подключает сервер `leads`.

```bash
scripts/claude-leads.sh      # сессия, где модели доступны только три инструмента
```

В сессии напишите «обработай новые заявки» или `/process-leads`. Чтобы получить
сводку, посчитанную по файлу, оберните сессию в сверку:

```bash
.venv/bin/python -m lead_assistant.session begin     # снимок «до»; печатает export-строки
# выполните напечатанные export, затем scripts/claude-leads.sh и /process-leads
.venv/bin/python -m lead_assistant.session end runs/<run_id> --report итог_модели.md
```

Автоматический прогон через Claude (`--backend claude`, пакет
`lead-assistant[claude]`) оставлен как вариант; он требует входа в Claude и в этой
поставке с настоящей авторизацией не проверялся.

## Сценарий работы менеджера

1. Утром и после обеда запустите `.venv/bin/process-leads` (или поставьте в cron).
2. Прочитайте сводку. Сначала раздел «Срочные (high)»: там цитата-основание и
   ближайшее действие. Затем «Проверить менеджеру»: повторы от одного контакта,
   заявки без контакта, истёкшие сроки, попытки управлять помощником.
3. Откройте заявку, проверьте черновик в поле `draft_reply`, добавьте
   подтверждённые факты (тариф, срок, статус груза) и отправьте ответ сами.
   Категорию и приоритет можно поправить: агент обработанные заявки не трогает.
4. Раздел «Ошибки и предупреждения» непустой — запустите прогон ещё раз; если не
   помогло, передайте `runs/<run_id>/` администратору.

## Как это устроено

| Часть | Файл | Ответственность |
|---|---|---|
| Хранилище | `storage.py`, `locking.py`, `models.py` | JSON, проверка данных, блокировка, атомарная запись |
| MCP-сервер | `server.py`, `draft_policy.py` | три инструмента, единый формат ошибок, проверка черновика, трейс |
| Правила агента | `rules.md`, `decision.py` | категории, приоритеты, черновики, границы |
| Модель | `llm.py`, `local_backend.py`, `backends.py` | загрузка и запуск модели, цикл агента, выбор при запуске |
| Сбор прогона | `runner.py`, `reconcile.py`, `report.py` | сессии, сверка «до/после», счётчики по ID, сводка, метрики |
| Оценка и диагностика | `evals.py`, `scoring.py`, `verify.py`, `diagnose.py`, `doctor.py`, `mcp_call.py`, `session.py` | качество, сверка с оригиналом, разбор сбоев |

Решения:

- **Локальная модель вместо облачной.** Запуск из коробки без учётных записей;
  данные клиентов остаются на сервере. Сервер `llama.cpp` и модель закреплены по
  версии и SHA-256. Протокол — OpenAI-совместимый, поэтому модель заменяема.
- **Модель вызывает инструменты сама, но решение о срочности выводит код.**
  Небольшая модель надёжно извлекает факты и ненадёжно взвешивает срочность. После
  `get_lead` она отвечает на вопросы о заявке и приводит дословные цитаты (срок,
  последствие, есть ли обращение к помощнику). Код проверяет цитаты по тексту
  заявки и выводит категорию и приоритет по таблице из `rules.md`. Вызов
  `update_lead` с другими значениями до сервера не доходит. Просьба «поставь
  приоритет high» в тексте заявки приоритет не меняет.
- **Черновик проверяется при записи.** Сервер отклоняет (`DRAFT_POLICY`) черновик,
  который утверждает что-то от имени компании («мы доставляем…», «уже проверяем»,
  «вернём деньги»), содержит число, которого нет в заявке, или написан не на языке
  заявки. Модель переписывает его; до файла такой текст не доходит.
- **Счётчики считает код, а не модель.** До и после прогона файл читается
  независимо; заявка засчитывается по состоянию файла. Повторные обращения с
  одного контакта находит код.
- **Короткие сессии.** За сессию модель разбирает не больше `--batch-size` заявок,
  следующая сессия начинается с чистого контекста и забирает оставшиеся. Заявка,
  не доведённая в одной сессии, не теряется.
- **Контракт записи.** `update_lead` разрешает только переход `new → processed`.
  Исходы различаются: `updated`, `unchanged` (повтор с теми же значениями),
  ошибка `CONFLICT` (уже обработана иначе) и ошибки с кодом. Повтор и конфликт
  файл не меняют. Для спама `draft_reply` обязан быть `null`, приоритет — `low`.
- **Запись.** Отдельный lock-файл `<файл>.lock`; под блокировкой данные
  перечитываются, запись идёт во временный файл в том же каталоге, затем `fsync`,
  `os.replace`, `fsync` каталога. Оформление файла сохраняется: меняется только
  строка обновлённой заявки. Файл в нераспознанном оформлении при первой записи
  приводится к отступу в два пробела; содержимое при этом не меняется.
- **Границы.** Модели объявляются только инструменты MCP-сервера проекта; раннер
  сверяет их список до первого обращения к модели и останавливается при
  расхождении. Текст заявки — данные: правила запрещают выполнять встроенные в
  него указания, а код не даёт им повлиять на категорию и приоритет.

## Данные и приватность

- **Модель получает** полные записи заявок, которые читает через `get_lead` (имя,
  контакт, текст), правила агента и дату прогона. С локальной моделью всё это
  остаётся на сервере. При `--llm-url` данные уходят в указанный вами сервис.
- **JSON хранится** на сервере по пути из `--leads-file` или `LEADS_FILE`; рядом
  создаётся `<файл>.lock`. Раннер копий файла не делает; `session begin` кладёт
  снимок «до» в каталог сессии и удаляет его командой `session end`.
- **Технический трейс** (`trace.jsonl`, `mcp_trace.jsonl`): идентификаторы, имена
  инструментов, коды исходов, длительности, токены. Текстов заявок, черновиков и
  секретов там нет. `run.json`, `summary.md` и `model_report.md` содержат
  пояснения по заявкам с цитатами и предназначены менеджеру. `dialog.jsonl` с
  полными текстами пишется только с `--save-dialog`.

## Ошибки и диагностика

```bash
.venv/bin/python -m lead_assistant.diagnose runs/<run_id>     # в каком слое сбой и что делать
.venv/bin/python -m lead_assistant.verify data/leads.original.json data/leads.json
.venv/bin/python -m lead_assistant.mcp_call get_lead '{"id": 3}'   # вызвать инструмент вручную через stdio
.venv/bin/python scripts/failure_drill.py                     # учебный разбор: сбой в каждом слое
```

Разбор идёт от данных к модели: сначала файл и трейс (хранилище, MCP, валидация,
сервер модели), и только если они чисты — поведение модели и правила.

| Признак | Слой | Действие |
|---|---|---|
| `STORAGE_CORRUPT`, `STORAGE_INVALID`, `DUPLICATE_ID` | данные | исправьте JSON: ошибка указывает строку или повторяющиеся ID |
| `LOCK_TIMEOUT`, `STORAGE_IO` | хранилище | другой процесс держит блокировку или нет места; повторите прогон |
| `MCP_UNAVAILABLE`, `TOOLS_MISMATCH` | MCP | `leads-doctor`; проверьте, что окружение установлено и путь к файлу верен |
| `INVALID_ARGUMENT`, `DRAFT_POLICY` в вызове | валидация | сервер отклонил параметры или черновик; текст ошибки называет нарушения |
| «модель не запущена», `LLM_UNAVAILABLE`, `LLM_HTTP_ERROR`, `CONTEXT_FULL`, `TIMEOUT` | сервер модели | `leads-doctor --live`, журнал `runs/<run_id>/llm_server.log`; при `CONTEXT_FULL` уменьшите `--batch-size` |
| `AUTH_FAILED` | авторизация | только для `--llm-url`: проверьте `LEADS_LLM_API_KEY` |
| `NO_UPDATE_ATTEMPT`, `NOT_READ`, `ANALYSIS_MISMATCH`, `MAX_TURNS` | модель | повторите прогон; сверьте с набором для оценки; возьмите модель крупнее |
| `CONFLICT`, `already_processed` | штатно | заявку обработал кто-то другой; она не перезаписана |

## Проверки качества

```bash
scripts/install.sh --dev
scripts/check.sh                                   # ruff, ruff format --check, mypy, pytest
.venv/bin/python -m lead_assistant.evals synthetic # фиксированный набор примеров через модель
.venv/bin/python -m lead_assistant.evals real --run runs/<run_id>/run.json  # сверка реальных заявок по ID
scripts/compare_models.sh имя qwen3-8b cpu         # сравнить модель на обоих наборах
scripts/acceptance.sh                              # приёмочный сценарий на чистой копии исходника
```

Ограничения: блокировка рассчитана на локальную файловую систему (на NFS
поведение `flock` зависит от настройки); ID заявок — целые числа или строки;
проверка черновика ловит типовые формулировки и не заменяет чтение менеджером.
