# История: первый вариант на Claude

Задание сначала требовало вызывать модель через авторизацию Claude. Этот вариант был
реализован и проверен до точки, где понадобился вход: на машине разработки авторизация
Claude для отдельного процесса отсутствовала (`01_runtime_and_auth_blocker.log`).
Затем заказчик изменил требование: модель может быть любой бесплатной и должна
запускаться из коробки. Рабочим путём стала локальная модель; материалы ниже сохранены
как история разработки и к приёмке финальной версии не относятся.

| Файл | Что это |
|---|---|
| `01_runtime_and_auth_blocker.log` | пробный запуск Claude Agent SDK и CLI: `Not logged in`, 0 токенов; прогон классифицирован как сбой авторизации |
| `02_clean_install_windows.log`, `02_clean_install_claude_variant.log` | чистая установка тогдашней версии архива |
| `prelim/` | предварительная проверка правил 1.0.0 и 1.1.0 субагентом Claude Opus из сессии разработки (не рабочий путь; см. `prelim/README.md`) |
| `screenshots/` | скриншоты терминала тогдашней версии |

Что из этого этапа осталось в продукте: MCP-сервер, хранилище, сверка прогона, набор
для оценки, проектные файлы для Claude Code (`.mcp.json`, `/process-leads`) и
необязательный бэкенд `--backend claude`.

Что этап дал для качества: предварительный прогон на Claude Opus показал, что правила
1.1.0 дают 18/18 и 15/15 при сильной модели. Это позволило отделить недостатки правил
от недостатков небольшой локальной модели, когда та на тех же правилах дала 12/18.
