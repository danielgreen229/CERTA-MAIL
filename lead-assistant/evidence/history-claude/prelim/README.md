# Предварительная проверка качества правил (не приёмочный прогон)

Рабочий путь проекта (Claude Agent SDK → Claude Code CLI → MCP) на машине разработки
заблокирован отсутствием авторизации Claude для отдельного процесса (см.
`../01_runtime_and_auth_blocker.log`). Чтобы не откладывать проверку правил, модель
вызывалась иначе:

- **Кто модель:** субагент Claude Opus, запущенный из авторизованной сессии
  разработки в десктоп-приложении Claude. Каждый прогон — новая сессия субагента.
- **Правила:** тот же файл `src/lead_assistant/rules.md`, прочитанный субагентом как
  системная инструкция; тот же запрос оператора с датой.
- **Инструменты:** те же три инструмента того же MCP-сервера через stdio, вызванные
  командой `python -m lead_assistant.mcp_call` (обёртка `tool.sh`).
- **Сверка:** `python -m lead_assistant.session end` по трейсу сервера и состоянию
  файла, затем `evals score` / `evals real` и `verify`.

Чем это отличается от рабочего пути и почему не засчитывается как приёмка:

1. У субагента были доступны и другие инструменты сессии; ограничение «только три
   MCP-инструмента» держалось на инструкции, а не технически.
2. Модель вызывала инструменты через командную строку, а не как собственные
   MCP-инструменты рантайма.
3. Телеметрии рантайма (токены, стоимость, длительность API) нет.
4. Точный идентификатор модели рантайм не сообщил; в `run.json` записана пометка.

Что проверка всё же показывает: поведение модели на этих правилах (категории,
приоритеты, черновики, устойчивость к встроенным в текст указаниям), работу сервера и
сверки на настоящих вызовах.

| Каталог | Правила | Набор | Результат |
|---|---|---|---|
| `rules-1.0.0-synthetic` | 1.0.0 | синтетический, 17 примеров + контрольная запись | 16/18 при первой оценке; после исправления проверки уточняющего вопроса — 17/18 (пример 116: `high` вместо `medium`) |
| `rules-1.0.0-real` | 1.0.0 | копия реальных заявок | 14/15 (заявка 14: `question` вместо `sale`) |
| `rules-1.1.0-synthetic` | 1.1.0 | синтетический | 18/18 |
| `rules-1.1.0-real` | 1.1.0 | копия реальных заявок | 15/15, сверка с оригиналом пройдена |

В каждом каталоге: `leads.json` (обработанный файл), `model_report.md` (итог модели),
`runs/<id>/run.json`, `summary.md`, `mcp_trace.jsonl`, `eval_report.json` или
`real_eval.json`, `args/` (аргументы вызовов `update_lead`).
