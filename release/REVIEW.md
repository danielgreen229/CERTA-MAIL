# REVIEW — отчёт проверки

Проект: AI-помощник менеджера по заявкам, версия 1.0.0, правила агента 1.2.1.
Архив: `lead-assistant-1.0.0.tar.gz`, SHA-256 `fc1fc3ea726a17e65da396f5c22d4957ee52e17c69456c0b86199bd7773cd294`.
Все пути ниже — относительно каталога `release/`.

## Итог: 9 из 10

Девять критериев подтверждены доказательствами. Критерий 2 открыт: установка и
приёмочный сценарий проверены из чистой распаковки на Windows 11 (Git Bash), а на
Ubuntu не проверены — в среде разработки нет Linux и нет доступа к серверу
(`evidence/08_no_linux_environment.txt`). Закрывается одним действием на сервере:

```bash
scripts/install.sh --dev && scripts/check.sh && scripts/acceptance.sh
```

Этим же действием на целевой системе подтверждается критерий 5 для ветки POSIX
(блокировка `flock`, `fsync` каталога): сейчас она проходит только статическую
проверку типов.

## Изменение постановки в ходе работы

Задание требовало вызывать модель через авторизацию Claude. Этот вариант был
реализован и упёрся во внешний блокер: на машине разработки авторизации Claude
для отдельного процесса нет (`evidence/history-claude/01_runtime_and_auth_blocker.log`:
`Not logged in`, 0 токенов). Заказчик изменил требование: модель может быть любой
бесплатной и должна запускаться из коробки, выбор модели — при запуске. Рабочим
путём стала локальная открытая модель Qwen3 на сервере `llama.cpp`. MCP-сервер,
хранилище, сверка и набор для оценки остались прежними; поддержка Claude Code
(`.mcp.json`, `/process-leads`) сохранена, бэкенд Claude Agent SDK стал
необязательным и с настоящей авторизацией не проверялся.

## Набор для оценки и сравнение моделей

Набор (`evals/cases.json`, 17 синтетических примеров и контрольная запись)
зафиксирован до настройки правил: покрыты все категории и приоритеты, жалоба в
форме вопроса, настоящий дедлайн, резкий тон без срочности, недостаток данных,
спам, фишинг и две попытки изменить инструкции агента. Контрольные суммы набора и
эталона не менялись с момента фиксации (`evidence/00_frozen_before_implementation.txt`).

## Разбор сбоев: как отличить слой

`python scripts/failure_drill.py` воспроизводит сбой в каждом слое на копии
исходных данных через настоящий MCP-сервер и разбирает его по трейсу
(`evidence/07_failure_drill.log`).

| Сценарий | Признак в трейсе | Слой | Что делать |
|---|---|---|---|
| Повреждённый JSON | `STORAGE_CORRUPT`, модель не вызывалась | хранилище | исправить файл: ошибка называет строку |
| Недопустимая категория | `INVALID_ARGUMENT` в вызове, остальные заявки записаны | валидация | данные или правило: текст ошибки перечисляет нарушения |
| Неподтверждённый черновик | `DRAFT_POLICY` в вызове | валидация | модель переписывает; при повторах смотреть правила черновика |
| Пропуск заявки | `NO_UPDATE_ATTEMPT`, инфраструктура чиста | модель | повтор прогона, набор для оценки, затем правила |
| Сервер MCP не стартует | `MCP_UNAVAILABLE`, обращений к модели 0 | MCP | `leads-doctor`; правила не трогать |
| Сервер модели недоступен | `LLM_UNAVAILABLE` | сервер модели | `leads-doctor --live`, `llm_server.log` |
| Сервис отклонил ключ | `AUTH_FAILED`, 0 токенов | авторизация | только для `--llm-url`: проверить ключ |

Настоящие случаи из работы: блокер авторизации Claude (не модель, а вход);
переполнение контекста (не модель, а раннер); остановка сервера модели сторонним
процессом при съёмке скриншотов — раннер показал `LLM_UNAVAILABLE`, слой
«рантайм», файл заявок не изменился.
