## Итог: 7 из 9

Подтверждены критерии 1–4, 6, 7, 9. Открыты:

- **5. Качество на CPU** — модель по умолчанию для сервера без видеокарты (`qwen3-8b`)
  на этом этапе набор для оценки не прогоняла. По замеру этапа 1 она проходит его на
  16/18 (ошибки категорий в примерах 105 и 107) и реальные заявки на 15/15. Сравнительные
  замеры по решению заказчика не проводились. Остаётся: прогнать
  `python -m lead_assistant.evals synthetic` на `qwen3-8b` на сервере и закрыть два
  примера правилом в коде.
- **8. Развёртывание** — проверено: `docker compose` с профилем GPU поднимает весь стек
  и проходит приёмку 11/11 внутри контейнера; финальный архив из чистой распаковки в
  каталоге с пробелами — `bash start.sh`, приёмка, резервная копия и восстановление,
  перезапуск. Не проверено: профиль CPU (`docker compose up -d` без GPU-файла) с полным
  прогоном модели. Сервер Ubuntu (12 vCPU / 12 ГБ) куплен, но SSH к нему с этой машины
  не проходит: трафик перехватывает VPN-клиент Happ, а исключение по приложению ещё не
  настроено. Остаётся одна команда на сервере:
  `docker compose up -d && docker compose exec web python -m lead_assistant.web.acceptance`.

## Ревью технического руководителя

| № | Воспроизведение | Причина | Исправление | Повторная проверка |
|---|---|---|---|---|
| 1 | `/process-leads` в Claude Code на Windows: `CONNECTION_CLOSED` | `.mcp.json` запускает `.venv/bin/python`, на Windows его нет | установщик кладёт лаунчер окружения в `.venv/bin` | повторная сессия Claude Code: 14 `updated` |
| 2 | Очередь проверки помечала почти все черновики «обязательства компании» | шаблон ловил темы клиента («стоимость», «договор») | шаблон только для обещаний и сумм | `test_commitment_detection_ignores_topics_and_catches_promises` |
| 3 | Фоновая задача запустила 14B на CPU | без сохранённого выбора сборка по умолчанию — `cpu` | сборка и модель задаются настройкой «Модель»; для сервера CPU это и нужно | задача продолжилась на Vulkan, 14/14 |
| 4 | Docker-образ не собирался: `pywin32==312` | `pip-compile` на Windows убрал маркер платформы | маркеры `sys_platform == 'win32'` возвращены, порядок пересборки в `requirements.README` | `docker compose build` |
